# Genesis Chronicle 核心功能測試清單

**用途**: 技術債清理過程中的回歸測試
**測試頻率**: 每完成一個模組的清理後執行
**預計時間**: 完整測試約 15-20 分鐘

---

## 🎯 測試原則

- ✅ 通過：功能正常運作
- ⚠️ 警告：功能運作但有小問題（UI、提示等）
- ❌ 失敗：功能無法使用或崩潰
- ⏭️ 跳過：此次清理未涉及的區域

---

## 📋 核心功能測試清單

### 1. 應用程式啟動 (Critical)
- [ ] 應用程式能正常啟動（無白屏）
- [ ] 主視窗正確顯示
- [ ] 無 console 錯誤（開發者工具檢查）
- [ ] 資料庫連接成功

**測試步驟**:
1. 關閉應用程式
2. 重新啟動 `npm run dev`
3. 觀察啟動過程和 console 輸出
4. 確認主畫面正常顯示

### 2. 專案管理 (Critical)

#### 2.1 創建新專案
- [ ] 點擊「新建專案」按鈕
- [ ] 填寫專案名稱和描述
- [ ] 選擇或不選擇模板
- [ ] 成功創建並進入專案編輯器

#### 2.2 載入現有專案
- [ ] Dashboard 顯示專案列表
- [ ] 點擊專案卡片能正常進入
- [ ] 專案資料正確載入（章節、角色等）

#### 2.3 專案設置
- [ ] 專案設置面板能打開
- [ ] 修改專案名稱、描述
- [ ] 設置保存成功

**測試步驟**:
1. 在 Dashboard 創建測試專案「Tech Debt Test」
2. 進入專案後退出
3. 重新載入確認專案存在
4. 修改專案設置並保存

### 3. 章節管理 (Critical)

#### 3.1 創建章節
- [ ] 點擊「新增章節」
- [ ] 填寫章節標題
- [ ] 章節列表正確顯示

#### 3.2 編輯章節
- [ ] 在編輯器輸入文字
- [ ] 自動儲存運作（2 秒後儲存）
- [ ] 重新載入後文字保留

#### 3.3 刪除章節
- [ ] 刪除章節功能運作
- [ ] 確認對話框顯示
- [ ] 刪除後章節不再顯示

**測試步驟**:
1. 創建測試章節「第一章 測試」
2. 輸入一段測試文字（至少 100 字）
3. 等待 2 秒確認自動儲存
4. 重新載入專案確認文字保留
5. 刪除測試章節

## 🚨 測試失敗處理流程

如果測試失敗：

1. **立即停止清理工作**
2. **記錄失敗細節**：
   - 失敗的功能
   - 錯誤訊息
   - 復現步驟
3. **檢查 git diff**：找出導致問題的修改
4. **回滾變更**：`git checkout -- [file]` 或 `git revert [commit]`
5. **分析原因**：為什麼這個修改會破壞功能
6. **修正策略**：調整清理方法，避免再次發生
7. **重新測試**：確認回滾後功能恢復
